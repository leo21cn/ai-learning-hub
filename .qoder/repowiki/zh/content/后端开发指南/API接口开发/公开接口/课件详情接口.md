## 架构总览
GET 课件详情的处理流程如下：
- 解析路径参数 courseware_id
- 调用服务层 get 获取课件对象（带 tags/materials/access_tokens 关联）
- 根据 access_mode 分支：
  - OPEN：直接返回
  - RESTRICTED：从请求中提取已解锁令牌哈希，若缺失或不在允许集合则拒绝
- 组装 CoursewareItem 返回

```mermaid

participant R as "路由 public_get_courseware"
participant S as "服务层 courseware.get/_to_item"
participant D as "数据库"
C->>R : GET /api/public/coursewares/{id}
R->>S : get(db, id)
S->>D : 查询课件及关联
D-->>S : 返回 Courseware 对象
alt access_mode == OPEN
S-->>R : Courseware 对象
R-->>C : 200 + 课件详情
else access_mode == RESTRICTED
R->>R : 读取 X-Token-Hash 或 Cookie lh_token_hash
alt 未提供或不在允许集合
R-->>C : 403 + 业务错误码 COURSEWARE_ACL_LOCKED
else 命中允许集合
S-->>R : Courseware 对象
R-->>C : 200 + 课件详情
end
end
```

### 令牌验证机制
- 令牌哈希来源优先级：
  1) 请求头 X-Token-Hash
  2) Cookie lh_token_hash
- 校验逻辑：
  - 若课件为 RESTRICTED，且未提供令牌哈希 → 403
  - 若提供的令牌哈希不在课件绑定的 access_tokens 的 value_hash 集合中 → 403
- 注意：GET 详情接口仅做“哈希匹配”，不执行明文令牌校验；明文校验由解锁接口完成。

```mermaid
flowchart TD
Start(["进入 public_get_courseware"]) --> Load["加载课件对象(含 access_tokens)"]
Load --> Mode{"access_mode ?"}
Mode --> |OPEN| ReturnOK["返回详情(200)"]
Mode --> |RESTRICTED| ReadHash["读取 X-Token-Hash 或 Cookie lh_token_hash"]
ReadHash --> HasHash{"是否提供哈希?"}
HasHash --> |否| ErrLocked["抛出 403(COURSEWARE_ACL_LOCKED)"]
HasHash --> |是| CheckAllowed{"哈希是否在允许集合?"}
CheckAllowed --> |否| ErrInvalid["抛出 403(COURSEWARE_ACL_LOCKED)"]
CheckAllowed --> |是| ReturnOK
```

### 解锁接口（配合 GET 使用）
- 方法：POST
- 路径：/api/public/coursewares/{courseware_id}/unlock
- 作用：用明文 token 换取已解锁令牌哈希，并写入 Cookie lh_token_hash，后续 GET 自动鉴权
- 行为要点：
  - OPEN 课件：无需解锁，仍会返回空 tokenHash 与该课件 id 列表
  - RESTRICTED 课件：校验明文 token 有效性，并检查该 token 是否被当前课件绑定
  - 成功后设置 Cookie lh_token_hash（httponly、samesite=lax、path=/、7天）

```mermaid
sequenceDiagram
participant C as "客户端"
participant U as "路由 public_unlock"
participant TS as "令牌服务 access_token.verify"
participant S as "服务层 courseware.get/_to_item"
participant D as "数据库"
C->>U : POST /api/public/coursewares/{id}/unlock {token}
U->>S : get(db, id)
S->>D : 查询课件及关联
D-->>S : 返回 Courseware 对象
alt access_mode == OPEN
S-->>U : Courseware 对象
U-->>C : 200 + {tokenHash : "", coursewareIds : [id]}
else access_mode == RESTRICTED
U->>TS : verify(token)
TS-->>U : AccessToken 或 None
alt 无效或未绑定
U-->>C : 401(INVALID_TOKEN)
else 有效且绑定
U->>U : 计算该 token 可访问的所有课件 id
U->>U : 设置 Cookie lh_token_hash=value_hash
U-->>C : 200 + {tokenHash, coursewareIds}
end
end
```

## 性能考虑
- 详情接口在获取课件时会预加载 tags、materials、access_tokens 关联，避免 N+1 查询。
- 返回材料列表时，服务端会从关联表读取 sort_order，确保顺序正确。
- 解锁接口会遍历所有 active token 进行常量时间比对，通常 token 数量较小，开销可控。

## 故障排查指南
- 404 课件不存在
  - 触发条件：课程 ID 不存在
  - 错误码：COURSEWARE_NOT_FOUND
  - 状态码：404
- 403 未授权（令牌缺失或无效）
  - 触发条件：RESTRICTED 课件未携带令牌哈希，或哈希不在允许集合
  - 错误码：COURSEWARE_ACL_LOCKED
  - 状态码：403
- 401 令牌无效（解锁接口）
  - 触发条件：明文 token 无效或未绑定到目标课件
  - 错误码：INVALID_TOKEN
  - 状态码：401

## 结论
- 课件详情接口以访问模式为核心控制点：OPEN 免鉴权，RESTRICTED 需令牌哈希。
- 令牌哈希优先从请求头 X-Token-Hash 读取，其次回退到 Cookie lh_token_hash。
- 解锁接口负责明文令牌校验并将哈希写入 Cookie，简化后续 GET 的鉴权流程。
- 错误码与状态码映射清晰，便于前端统一处理。

### 安全考虑与最佳实践
- 令牌传输
  - 优先使用 HTTPS，避免明文令牌泄露
  - 解锁成功后，服务端设置 httponly、samesite=lax 的 Cookie，降低 XSS 风险
- 令牌存储
  - 服务端仅存储令牌哈希，不保存明文
  - 前端不应缓存明文令牌，尽量通过解锁接口动态获取
- 令牌生命周期
  - 定期轮换令牌，必要时重新生成
  - 限制令牌绑定范围，最小权限原则
- 前端交互
  - 首次访问 RESTRICTED 课件时，先调用解锁接口，再请求详情
  - 若返回 403，提示用户输入令牌或联系管理员
