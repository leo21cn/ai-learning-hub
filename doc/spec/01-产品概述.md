# 01. 产品概述

> 本章面向产品 / 业务 / 决策角色，回答 Learning Hub「是什么、为什么、为谁做、做什么」。

## 1. 产品定义

**Learning Hub** 是一个面向企业内部的学习资料检索与运营平台。它把企业内零散的学习内容（视频课程、PDF 文档、PPT 课件）通过统一的"课件"概念聚合起来，并提供：

- **前台**: 一句话自然语言搜索的极简检索体验；
- **后台**: 课件 / 分类 / 标签 / 素材的全生命周期运营能力。

产品名称 **Learning Hub** 在 UI 上以品牌化标题形式同时出现在前台与后台顶部，强调"学习中枢"的品牌定位。

## 2. 目标用户与场景

### 2.1 学习者（前台用户）

| 维度 | 说明 |
| ---- | ---- |
| 身份 | 企业内部员工，无须登录即可检索 |
| 典型诉求 | "我想找一份项目管理入门的资料"、"帮我看看团队最近有没有敏捷开发相关的视频" |
| 核心路径 | 进入首页 → 在搜索框输入自然语言 → 查看 AI 返回的课件列表 → 点击课件查看 |
| 痛点 | 资料分散在各个系统，关键词搜索命中率低 |

### 2.2 管理员（后台用户）

| 维度 | 说明 |
| ---- | ---- |
| 身份 | 持有 Admin Token 的运营 / 培训管理者 |
| 典型诉求 | 新建一门课程、整理分类、上传新视频、为已有课件补充标签 |
| 核心路径 | Token 登录 → 进入对应模块 → 完成增 / 删 / 改 / 查 |
| 痛点 | 内容来源杂、上传零散，缺乏统一素材库与分类体系 |

## 3. 核心价值主张

1. **极简入口**: 前台只保留一个搜索框，把"找学习资料"压缩到一句话的距离。
2. **AI 智能搜索**: 通过自然语言理解，把模糊诉求（"项目管理相关的课程"）直接映射到具体课件。
3. **结构化运营**: 后台通过"课件 - 分类 - 标签 - 素材"四层结构，覆盖内容从入到出的完整生命周期。
4. **品牌统一**: 前后台统一标题与视觉风格，强化"Learning Hub"品牌认知。

## 4. 业务范围

### 4.1 范围内（In Scope）

- 课件（Courseware）的创建、检索、编辑、发布。
- 分类（Category）的三级树形管理。
- 标签（Tag）的扁平化管理。
- 素材（Material）的上传与管理，支持 MP4 / PDF / PPT / PPTX，单文件 ≤ 200MB。
- 基于 Token 的管理员鉴权。
- 前台基于 AI 语义理解的课件检索。
- 课件访问 Token（AccessToken）配置与校验（开放 / 受限双模式）：受限课件对所有用户可见可搜，但需输入有效 Token 才能进入详情。
- **课件详情页提供三大主流素材格式（PDF / PPT / MP4）的行内浏览能力**：PDF 采用 Word 式连续阅读，PPT 采用幻灯片式单页呈现，MP4 采用简化流媒体式播放。PPT 在上传时由后端自动转换为 PDF，前端通过 PDF.js 渲染。详见 [03 §5a](./03-前台门户规格.md)。

### 4.2 范围外（Out of Scope，当前版本）

- 用户账号体系 / 学习者登录：当前版本的 Token 仅作密码式分发，不绑定学习者个人身份。
- 课件的学习进度跟踪、笔记、评论、考试。
- 课件的付费 / 会员机制。
- 移动端 App / 微信小程序。
- 多语言切换（UI 当前为中文单一语言通道）。
- 富媒体编辑器，课件描述仅支持多行纯文本。

## 5. 术语表

| 术语 | 含义 |
| ---- | ---- |
| 课件（Courseware） | 学习门户的最小检索 / 运营单元，包含标题、作者、描述、分类、标签、关联素材 |
| 分类（Category） | 树形组织结构，最多 3 层，根级 → 二级 → 三级 |
| 标签（Tag） | 扁平的能力 / 主题词条，可任意挂载到课件 |
| 素材（Material） | 课件内的物理资源载体，支持视频 / PDF / PPT / PPTX |
| 预览 PDF（preview_pdf_path） | PPT/PPTX 上传后由后端 LibreOffice 转换生成的 PDF 路径；为 NULL 表示未转换或失败未重试。仅供后台 / P-VIEWER 使用 |
| PPT 转 PDF 服务 | 后端 `app/services/ppt_to_pdf.py`，调用本地 `libreoffice --headless --convert-to pdf`；失败仅记录日志，不阻断上传 |
| P-VIEWER | 前台素材在线浏览页 `?view=viewer&id=<materialId>&cw=<coursewareId>`，按素材类型提供三种样式 |
| Admin Token | 管理后台的统一鉴权凭据，本地演示值为 `demo` |
| 访问 Token（AccessToken） | 课件级的访问密码式凭据；与课件是 M:N 关系，一个 Token 可解锁多个课件，反之亦然；未配置 Token 的课件保持开放访问 |
| AI 智能搜索 | 前台基于自然语言的检索，结果可能包含 0 个或多个课件 |

## 6. 成功度量（建议指标）

| 指标 | 含义 | 建议基线 |
| ---- | ---- | -------- |
| 搜索命中率 | 搜索返回课件数 / 总搜索次数 | ≥ 60% |
| 平均检索耗时 | 从点击搜索到结果展示耗时 | ≤ 2s（P95） |
| 课件覆盖度 | 已发布课件 / 内部资料总数 | ≥ 80% |
| 管理员活跃度 | 周活跃管理员数 | ≥ 2 人 |

## 7. 风险与约束

| 风险 | 影响 | 缓解策略 |
| ---- | ---- | -------- |
| AI 搜索效果依赖语料与提示词 | 用户体验 | 提供运营后台的"AI 调试 / 反馈"通路（未来版本） |
| 管理员单一 Token，权限不可细分 | 安全 | 短期接受；中期规划账号 + RBAC |
| 课件访问 Token 通过线下渠道分发，可能外泄 | 课件内容扩散 | 后台提供重新生成 Token 与即时吊销能力；前端输入仅记忆至 localStorage，关闭/清除浏览器可失效 |
| 大文件上传（200MB）易超时 | 可用性 | 引入分片上传 + 断点续传 |
| 应用部署在 Docker 容器内（`/app/storage/documents`） | 文件持久化 | 容器外挂载 PV / 对象存储 |
